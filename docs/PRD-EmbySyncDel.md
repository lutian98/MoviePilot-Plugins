## 1. 背景与问题

媒体库的日常运维里，「删片」从来不是点一下那么简单。在 Emby 里删掉一个条目只是删掉了**索引**，
真正占空间和占数据库的内容分散在五处：

1. MoviePilot（下称 MP）的**整理记录**；
2. 媒体库里的**硬链接 / 软链接文件**（`link/Movie/...`）；
3. **源文件**（`PT/保种/...`，Transmission 正在做种的那份）；
4. 下载器里的**任务**，以及由 CrossSeed 生成的**辅种**任务；
5. 目录里的**附属文件**：`.nfo`、海报、背景图、字幕、外挂音轨。

第 5 项在 2026-10 的实测里被反复证实：`link/Movie` 下 **124 个标题目录只剩 nfo 和海报**
（396.8 MB），`Strm/Media/Movie` 下另有 **64 个空目录**。这些「残壳」不只是占空间——
媒体服务器下次扫描会顺着目录结构把条目**重建**出来，形成删不掉的幽灵条目
（同期 Plex 侧清出 **52 条**指向已不存在文件的僵尸记录）。

已有的联动删除方案在真实环境里会整体静默失效，原因有三类：

| 失效原因 | 具体表现 |
| --- | --- |
| 事件名写死 | 只认 `library.deleted` / `ItemDeleted`，Emby 换版本或换通知插件后插件整体哑掉 |
| 路径要求完全相等 | Emby 上报 `.strm`、整理记录里是 `.mkv` → 永久失配 → 静默放弃，无任何日志 |
| 拿不到媒体身份就退出 | 事件缺 `ProviderIds` 时直接放弃，不做路径兜底 |

此外，宿主侧还有一个隐蔽的坑：MP 的 Emby 解析器**只读 form-data 的 `data` 字段或查询参数，
不读 JSON 请求体**。Emby 的 Webhooks 若选 JSON 提交，事件在 MP 入口就被丢弃——HTTP 200、无日志，
任何挂在事件总线上的插件都收不到。

**结论**：需要一套「事件进得来、条目匹配得上、五处删得干净、删错了拦得住」的联动删除实现。

## 2. 目标与非目标

### 2.1 目标

- **G1** 媒体服务器删除条目后，自动清理 MP 整理记录、媒体库文件、源文件、下载任务（含辅种）。
- **G2** 删除后不留附属文件残壳与空目录，避免媒体服务器重建幽灵条目。
- **G3** 匹配以**媒体身份 + 路径**为准，宁可放弃也不猜；误删风险由多层护栏拦死。
- **G4** 全链路可观测：每条删除都有历史记录与（可选）通知，失败保留记录可补删。
- **G5** 兼容 Emby 不同版本/不同通知插件的事件名与报文写法。

### 2.2 非目标

- **N1** 不做媒体服务器条目本身的删除（Emby 侧删除是触发源；Plex 条目清理不在本插件职责内）。
- **N2** 不做媒体库扫描、刮削、整理（交给 MP 的整理链）。
- **N3** 不做跨盘迁移 / 重命名。
- **N4** 不提供绕过宿主事件总线的匿名直投入口（1.5.0 起移除，减少可被伪造的删除面）。

## 3. 用户与场景

**用户**：自建媒体库的个人管理员（单机部署，MP + Emby + Plex + qBittorrent/Transmission + CrossSeed）。

| 场景 | 触发 | 期望结果 |
| --- | --- | --- |
| S1 单部影片删除 | 在 Emby 删除一部电影 | 五处全清，通知给出逐项清单 |
| S2 剧集删除 | 删除整部剧或某一季 | 逐集清理，容器级事件不误伤其它集 |
| S3 换版重下 | 旧版本被删除、新版本入库 | 只清旧版，不碰新版文件与记录 |
| S4 批量清历史 | 一次性删除多部旧片 | 逐条独立处理，单条失败不影响其余 |
| S5 误删拦截 | 事件路径与整理记录标题不符 | 跳过该条并保留记录，通知说明原因 |

## 4. 术语

| 术语 | 含义 |
| --- | --- |
| 整理记录（TransferHistory） | MP 里「源文件 → 媒体库目标」的一条搬运记录，是删除动作的锚点 |
| 源文件 | 下载器目录里的原始媒体文件（`PT/保种/...`） |
| 媒体库文件 | MP 整理后落在库目录的硬链接/软链接（`link/...`） |
| strm 占位 | 云盘场景下媒体库里只有指向 115 的 `.strm` 文本文件 |
| 辅种 | CrossSeed 生成的、与主体共享同一份文件的任务，不落库、靠标签识别 |
| 残壳 | 媒体文件已删除、只剩附属文件或空目录的标题目录 |

## 6. 功能需求细则

### FR-1 事件接入与兼容

- **FR-1.1** 通过宿主事件总线接收 `EventType.WebhookMessage`，handler 必须是 `sync_del_by_webhook`。
- **FR-1.2** 事件名白名单可配置，默认收 `library.deleted`、`ItemDeleted`、`item.deleted`；
  另支持 `library.removed`、`media.deleted`、`media_del` 及自定义补充项。
- **FR-1.3** 报文宽容解析：事件名兼容 `Event/event/eventType/type`；条目兼容 `Item`（单条）与
  `Items`（数组，逐条处理）；名称兼容 `Name/name`（缺年份时按 `名称 (年份)` 补全）；
  路径兼容 `Path/path`。
- **FR-1.4** 同一事件 **60 秒**内只处理一次（宿重重投 / 双入口重放去重）。
- **FR-1.5** **容器级事件不处理**：条目类型为 `Folder/Series/Season/CollectionFolder/BoxSet/Collection`
  时跳过——实测这类事件大量来自换版重建，按目录名匹配会误删仍在库里的影片。

**验收**：换事件名后插件仍工作；同一条事件重投两次只产生一条历史；容器级事件零删除动作。

### FR-2 媒体身份解析与记录匹配

三级兜底，逐级降级，**任何一级都不允许「按标题猜」**：

1. **事件身份**：`ProviderIds`（Tmdb/Imdb/Tvdb）；
2. **ProviderIds 补充**：事件未带身份时从条目属性读取；
3. **路径匹配**：要求路径对应（目录或文件名主干相等，与后缀无关），
   且**命中的整理记录必须唯一**，并叠加标题防误删校验。

匹配规则：

- **FR-2.1** 路径比较忽略扩展名：`影片.strm` 与记录里的 `影片.mkv` 视为同一目标。
- **FR-2.2** 命中多条记录且无法用身份收敛时 → 放弃并告警，不执行任何删除。
- **FR-2.3** `_title_guard` 开启时，整理记录标题必须出现在被删媒体名中，否则跳过并保留记录。

**验收**：strm 事件能命中 mkv 记录；同名不同片被 title_guard 拦下；多条命中时零删除。

### FR-3 五处删除动作

按固定顺序执行，**整理记录最后删**：

| 顺序 | 对象 | 规则 |
| --- | --- | --- |
| 1 | 媒体库文件 | 必须位于「媒体库路径映射」范围内；strm 占位与真实媒体文件分别处理 |
| 2 | 源文件 | 必须是媒体文件，且位于 `source_roots` 允许范围内 |
| 3 | 附属文件 / 空目录 | 见 FR-4 |
| 4 | 下载任务 | 主任务 + 转种 + 辅种（递归，最大深度 5）；动作可选「删除任务与文件」或「暂停任务（保留文件）」 |
| 5 | 整理记录 | 仅当前 1–4 步全部成功才删除；否则保留以便补删 |

- **FR-3.1** 辅种不落库，靠下载器里的标签识别（默认标签 `辅种`，可配置）。
- **FR-3.2** 删除任务前先确认文件归属，同一 hash 只处理一次，防环路。
- **FR-3.3** 媒体库文件在 MP 内不可见（挂载缺失/路径配错）→ 判失败、保留整理记录，不静默成功。

**验收**：删除一部片后，库文件、源文件、任务、辅种、记录全部消失；人为制造挂载缺失时记录被保留且通知说明原因。

### FR-4 附属文件与空目录清理（1.5.7）

- **FR-4.1** 删除媒体文件后，自底向上清理空目录，最多回退 **8 层**，遇受保护根目录即停止。
- **FR-4.2** 目录内**只剩附属文件**时，先删除这些文件再 `rmdir`，否则永不满足「空目录」条件，
  残壳会一直留着（这正是 2026-10 实测 124 个残壳目录的成因）。
- **FR-4.3** 附属文件白名单：字幕（ass/ssa/srt/sup/sub/idx/vtt/smi/sami/ttml）、外挂音轨
  （mka/flac/aac/ac3/dts/m4a/ape/wav）、元数据与图片（nfo/txt/url/sfv/md5/sha1/cue/log/tmm/jpg/jpeg/png/webp/bmp/gif）。
- **FR-4.4** **fail-closed**：目录内出现子目录、媒体文件或任何未知扩展名 → 一律不碰并停止上收。
  多集剧集目录（还有其他集）因此永远不会被清空。
- **FR-4.5** 开关 `clean_aux` 控制，默认开启。

**验收**：只剩 nfo+海报+字幕的目录 → 整个目录消失；同目录还有其它集 → 目录与附属文件都不动；
出现未知扩展名 → 不动；开关关闭 → 只做空目录清理。

### FR-5 安全护栏

| 护栏 | 规则 |
| --- | --- |
| 演练模式 | `dry_run` 默认开，只出清单不删除；关闭后才真实执行 |
| 路径白名单 | 媒体库文件必须在「媒体库路径映射」内；源文件必须在 `source_roots` 内 |
| 排除路径 | `exclude_path` 命中的路径完全静默 |
| 标题校验 | `title_guard` 默认开，标题不符即跳过 |
| 唯一命中 | 多条候选记录无法收敛时放弃 |
| 幂等去重 | 60 秒窗口内同一事件只处理一次 |
| 并发锁 | 事件处理持锁，避免同一记录被并行清理 |
| 顺序保证 | 整理记录最后删，失败可重试 |

**验收**：以上每条都有对应单元测试；任一护栏触发时不得产生任何删除动作。

### FR-6 通知与历史

- **FR-6.1** 每次处理写插件历史（最多 200 条，详情页分页 20 条/页）。
- **FR-6.2** 通知可开关，包含逐项动作清单与结果；有海报时附图。
- **FR-6.3** 提供只读接口 `GET /history` 与 `GET /delete_history`，均要求宿主 `apikey` 鉴权。

### FR-8 自测与回归

- **FR-8.1** 单测不依赖 MoviePilot 运行时（桩掉 `app.*`），`python -m unittest discover -s tests/v3 -t .` 可跑。
- **FR-8.2** 必须有端到端沙箱用例：在真实临时目录上仿真「媒体服务器库 + MP 库 + 保种目录」，
  跑通全链路并验证**同目录其它影片毫发无损**。
- **FR-8.3** 入口级用例：从事件注册入口（而非直接调内部方法）走一遍，防止「入口没接上」类缺陷。
- **FR-8.4** 当前用例数：**83**，全绿。

## 7. 非功能需求

- **NFR-1 正确性优先于覆盖率**：任何不确定情形一律放弃删除并留痕；「没删」可补，「误删」不可逆。
- **NFR-2 可观测**：每次处理产出结构化历史（时间、事件、匹配记录、逐项动作、失败原因）。
- **NFR-3 兼容性**：跟随 MP V3 插件 SDK（`_PluginBase` 抽象方法需完整实现，否则插件无法实例化）。
- **NFR-4 性能**：单条事件处理应在秒级完成；整理记录查询分页上限 200 条，避免全表扫描。
- **NFR-5 幂等**：重复事件不产生重复删除动作。

## 8. 关键流程

```
Emby 删除条目
  → Webhook（form-data 的 data 字段）→ MP /api/v1/webhook/
  → 宿主事件总线 WebhookMessage
  → sync_del_by_webhook
      → 事件名过滤 / 容器级事件跳过 / 60s 去重
      → 身份解析（ProviderIds → 路径）
      → 路径映射（媒体服务器路径 → MP 路径）
      → 匹配整理记录（唯一性 + title_guard）
      → 逐项执行：库文件 → 源文件 → 附属文件/空目录 → 任务与辅种
      → 整理记录（仅全部成功）
  → 历史 + 通知
```

## 9. 边界与失败处理

| 情形 | 处理 |
| --- | --- |
| 事件缺媒体身份 | 退回路径匹配；路径对不上则放弃 |
| 事件路径在映射范围外 | 跳过文件删除，保留记录并告警 |
| 媒体库文件在 MP 内不可见 | 判失败、保留记录（挂载缺失/路径配错） |
| 命中多条整理记录 | 放弃并告警 |
| 标题与媒体名不符 | 跳过该条，保留记录 |
| 目录内还有其它媒体 | 不清理该目录 |
| 未知扩展名 | 不清理（fail-closed） |
| 事件重复投递 | 60 秒内只处理一次 |
| 单条删除失败 | 不影响同批其它条目 |

## 10. 验收标准（可执行）

1. 删除一部电影 → 库文件、源文件、下载任务、辅种、整理记录五项全清，通知给出清单。
2. 只剩 nfo/海报/字幕的目录 → 目录整体消失，父目录不被误删。
3. 多集剧集目录删掉一集 → 目录与其余集、海报全部保留。
4. 目录内出现未知扩展名 → 零删除。
5. `dry_run` 开启 → 只有清单，磁盘与下载器零变化。
6. 事件路径与记录标题不符 → 跳过并保留记录。
7. 同一事件投递两次 → 只产生一条历史。
8. 全量单测通过（当前 83 项）。

## 12. 已知限制与后续

- **L1** 插件只负责 Emby 侧触发；Plex 条目需 Plex 自身扫描或另行清理（MP 中启用 Plex 可减少僵尸）。
- **L2** 修改自定义规则/插件后，MP 需重启或重载才会生效。
- **L3** 容器级（文件夹）删除事件一律跳过：整季/整剧删除依赖媒体服务器逐条发出的条目事件。
- **L4** 附属文件白名单是「显式枚举」策略，新格式（如 `.lrc`）需手动加入，否则按 fail-closed 不清理。
- **后续候选**：① 删除结果与 Plex 条目联动校验；② 残壳巡检命令（列出全库仅剩附属文件的目录）；
  ③ 批量清理的进度回报。
