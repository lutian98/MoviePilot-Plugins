# MoviePilot Plugins（Emby 联动删除）

适用于 **MoviePilot V3（v3.0.0 及以上）** 的插件集合。

当前包含 1 个插件：**[Emby 联动删除](#emby-联动删除)** —— 媒体服务器删除影片后，同步清理 MoviePilot 侧的整理记录、源文件、媒体库文件与下载任务。

> ⚠️ **Emby 用户必读**：MoviePilot 的 Emby 报文解析器**只认表单字段 `data`/查询参数，不读 JSON 请求体**，
> 而 Emby 的 Webhooks 插件发的正是 JSON —— 事件会被 MP **静默丢弃**（HTTP 仍回 200，日志无报错），
> 任何插件都收不到真实删除事件。**必须**在 Emby 与 MP 之间加一层格式转换转发：
> 见 **[relay/（零依赖，单文件可跑）](./relay/README.md)**。Plex / Jellyfin 不受影响。

> **破坏性说明**：本插件会删除文件（媒体库文件、源文件、strm 占位文件）与下载任务，操作不可逆。
> 默认开启「演练模式」：只发通知列出将要删除的内容，不做任何删除。请先用演练模式核对清单。

## Emby 联动删除

`EmbySyncDel` · v1.0.3

| 项目 | 说明 |
| --- | --- |
| 触发源 | 媒体服务器删除通知（Webhook）→ MoviePilot `/api/v1/webhook` → 本插件 |
| 处理内容 | 整理记录、源文件、媒体库文件与空目录、strm 占位文件、下载任务（主任务 / 转种 / 辅种） |
| 适用媒体服务器 | Emby（其它会向 MoviePilot 发送删除事件的媒体服务器同样可用） |
| 默认模式 | 演练（只出清单，不删除） |

### 为什么需要这个插件

媒体服务器删除条目后，MoviePilot 侧的整理记录、下载任务与残留文件不会自动跟着消失：整理记录留着 → 再次订阅同一部片时会被当成"已整理"而不再下载；下载任务留着 → 继续做种占带宽；文件留着 → 占空间且媒体服务器下次扫描可能把条目加回来。

市面上已有的同类插件在两类环境下会**整体静默失效**，本插件正是为解决它们而写：

| 问题 | 已有插件的做法 | 本插件的做法 |
| --- | --- | --- |
| 事件名被写死 | 只认 `library.deleted` / `ItemDeleted`，媒体服务器换事件名即失效 | **事件名可配置**，默认同时接受 3 种常见写法 |
| strm / 软链接媒体库匹配不上 | 要求上报路径与整理记录 `dest` **完全相等**；strm 库上报 `影片.strm`，记录里是 `影片.mkv` → 永远失配 → 静默放弃 | **后缀无关匹配**：先按媒体身份，再按**目录 / 文件名主干**匹配，多分辨率、多版本一并命中 |
| 媒体身份缺失即放弃 | 新版要求唯一媒体身份，拿不到就退出 | **三级兜底**：事件身份 → 报文 ProviderIds → **媒体路径匹配**（真实 Emby 删除报文常常不带 ProviderIds）；仍要求路径对应、命中唯一，绝不按标题猜 |
| 真实事件根本到不了插件 | 无人处理：MP 的 Emby 解析器只认表单 `data`/查询参数，Emby 发的 JSON body 被**静默丢弃**（HTTP 200、无日志） | 在 Emby 与 MP 之间加一层**格式转换转发**：见 [relay/](./relay/README.md)（零依赖，单文件可跑） |

### 安装

**方式一：插件市场（推荐）**

MoviePilot → 设定 → 插件市场 → 右上角「插件仓库」→ 添加：

```
https://github.com/lutian98/MoviePilot-Plugins
```

保存后刷新市场，搜索「Emby 联动删除」并安装。

**方式二：手动放置**

把 `plugins.v3/embysyncdel` 整个目录放到 MoviePilot 的 `app/plugins/` 下，重启 MoviePilot。

### 配置

| 配置项 | 默认值 | 说明 |
| --- | --- | --- |
| 启用插件 | 关 | 关闭时插件对任何事件都不做处理 |
| 发送通知 | 开 | 演练、未匹配、执行完成都会发通知 |
| **演练模式** | **开** | 只发通知列出将删除的内容，不做任何删除。核对无误后再关闭 |
| 清理插件历史 | 关 | 打开并保存配置即清空本插件的执行历史 |
| 接受的删除事件名 | `library.deleted,ItemDeleted,item.deleted` | 逗号分隔；不确定媒体服务器发哪个事件名时，三种都留着即可 |
| **媒体库路径映射** | 空 | **必填**。格式：`媒体服务器路径#MoviePilot路径`，一行一个。详见下文 |
| 排除路径 | 空 | 一行一个；媒体路径包含其中任一条即跳过（如不处理的二级分类） |
| 删除源文件与传输文件 | 开 | 关闭后只清理整理记录与下载任务，不删可见文件 |
| 同时处理辅种 | 开 | 递归清理转种 / 辅种插件记录的关联任务 |
| 标题防误删校验 | 开 | 要求整理记录标题出现在删除媒体名中，避免误删同目录的其它影片 |
| 下载任务处理方式 | 删除任务与文件 | 可选「暂停任务（保留文件）」——只想停止做种而不删数据时用 |

### 路径映射怎么填

填写「**媒体服务器看到的媒体库根目录**」→「**MoviePilot 容器内的媒体库根目录**」：

```
/mnt/user/Media/Strm/Media#/downloads/link
```

- 分隔符用 `#`（推荐，Windows 盘符路径也不会歧义）；`:` 亦兼容
- 支持多行、多个媒体库
- 映射只用于**定位**整理记录与文件，与文件后缀无关
- 若媒体服务器与 MoviePilot 看到的是同一套路径，可填 `源#源` 或留空（留空时插件不会删除媒体库文件，只会处理整理记录与下载任务，并在通知中说明）

> 映射填错的典型表现：通知里出现「**未找到匹配的整理记录**」，并附带「媒体服务器路径」与「匹配用路径」两行，对照即可定位。

### 工作原理

```
媒体服务器删除条目
      ↓ 删除事件（Webhook）
MoviePilot /api/v1/webhook
      ↓ 事件总线
本插件 sync_del_by_webhook
      ↓ ① 事件名过滤（可配置）
      ↓ ② 排除路径过滤
      ↓ ③ 媒体身份解析（事件 → ProviderIds 兜底；拿不到则告警退出）
      ↓ ④ 路径映射 → 查找整理记录（身份查询 + 目录 / 文件名主干匹配）
      ↓ ⑤ 逐条处理：
            删除媒体库文件 → 删除源文件 → 清理空目录
            → 处理下载任务（主任务 + 转种 + 辅种）
            → 最后删除整理记录（清理失败则保留，便于下次重试）
      ↓ ⑥ 清理 strm 占位文件（只删占位，不动真实媒体文件）
      ↓ ⑦ 通知执行结果 + 写入插件历史
```

设计上刻意遵守三条纪律：

1. **不确定就不动手**：身份缺失、路径不在映射范围内、标题对不上，一律跳过并告警，绝不猜。
2. **记录最后删**：整理记录是跨文件系统、下载器清理失败后的唯一重试依据。
3. **只删该删的**：媒体库文件必须位于映射范围内；源文件必须是媒体文件；strm 占位与真实文件分别处理，互不重复。

### 常见问题

**Q：删了媒体服务器的条目，插件没反应？**
逐项检查：插件是否启用 → 事件名是否在「接受的删除事件名」里（看 MoviePilot 日志中收到的事件名）→ 媒体路径是否命中「排除路径」→ 通知里是否出现「未识别媒体身份」。

**Q：提示「未找到匹配的整理记录」？**
九成是路径映射不对。通知里会同时给出「媒体服务器路径」和「匹配用路径」，对照真实目录修正映射。其次检查该片是否真的由 MoviePilot 整理入库（手动放进媒体库的文件没有整理记录）。

**Q：strm 库会删掉我的网盘 / 源文件吗？**
不会。strm 占位文件与真实媒体文件分别处理：插件只删 `.strm` 占位、整理记录里记的真实媒体文件与源文件。真实文件在网盘（未挂载到 MoviePilot）时自然删不到，只清理本地记录与占位。

**Q：只想停止做种，不想删文件？**
把「下载任务处理方式」改成「暂停任务（保留文件）」。

**Q：误删了能恢复吗？**
不能。文件删除不可逆，请务必先用演练模式核对清单，稳定后再关闭演练模式。

### 开发与测试

插件核心逻辑（事件名过滤、路径映射、后缀无关匹配、演练流程、防误删护栏、删除链路）
与宿主解耦，可在没有 MoviePilot 的环境直接跑测试：

```bash
python -m unittest discover -s tests/v3 -t .   # 或 pytest tests/v3
python .github/scripts/check_plugin_versions.py  # 索引与代码版本一致性
```

- 测试位于 `tests/v3/embysyncdel/`（官方约定：不要放进插件源码目录）。
- `tests/app_stub.py` 用最小实现桩掉宿主 `app.*`，因此不需要安装 MoviePilot。
- `test_e2e_sandbox.py` 在真实临时目录上仿真「媒体服务器媒体库 + MoviePilot 媒体库 +
  保种目录」，跑通完整删除链路，并验证同目录其它影片毫发无损。
